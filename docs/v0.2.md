# Shiva V0.2 Goal

Implement Shiva's first proper persistent memory system using exactly three conceptual memory layers.

## 1. Working Memory

Working memory represents the current conversation/session.

Store:

```text
conversations
messages
```

Use recent conversation messages to preserve conversational continuity.

Example:

User:
"I'm considering Singapore."

Later:

"How long should I stay there?"

Shiva should understand that "there" means Singapore.

Working memory is NOT vector-search memory.

Do not send unlimited conversation history to Gemma.

Use a configurable recent-message limit initially.

---

## 2. Episodic Memory

Episodic memory represents things that happened.

Examples:

```text
Yash selected an RTX 3090 for Shiva development.

Shiva V0.1 was successfully deployed.

A particular decision was made on a particular date.
```

Support temporal information:

```text
occurred_at
valid_from
valid_until
```

---

## 3. Semantic Memory

Semantic memory represents knowledge Shiva learns about the user.

Examples:

```text
Yash prefers aisle seats.

Shiva should support English first.

A person has a particular relationship with Yash.

A stable personal/project fact.
```

Support semantic subtypes:

```text
fact
preference
relationship
project_fact
profile
```

Do NOT implement procedural memory yet.

# Retrieval

When Shiva receives a meaningful request:

1. generate a query embedding
2. search active semantic memories
3. search active episodic memories
4. use cosine similarity
5. rank using a lightweight combination of:

   * semantic similarity
   * importance
   * recency
6. inject only the best relevant memories into Gemma

Do NOT inject the entire memory database.

Update:

```text
last_accessed_at
access_count
```

for memories actually used.

---

# Memory Extraction

After an interaction finishes, evaluate whether the USER supplied information worth remembering.

The user's streamed response must NOT wait unnecessarily for long-term memory processing.

Memory extraction should happen after the response where practical.

Failure of memory extraction must NOT cause the normal chat response to fail.

Use the existing Shiva reasoning model with a dedicated memory-extraction prompt.

Require structured JSON validated with Zod.

Example:

```json
{
  "memories": [
    {
      "shouldRemember": true,
      "memoryType": "semantic",
      "semanticType": "preference",
      "content": "Yash prefers aisle seats when flying.",
      "importance": 0.8,
      "confidence": 0.95
    }
  ]
}
```

Or:

```json
{
  "memories": []
}
```

Do not store filler such as:

```text
okay
thanks
hello
yes
```

unless context makes it genuinely meaningful.

# Duplicate / Contradiction Handling

Before inserting a new semantic memory:

1. retrieve highly similar active semantic memories
2. classify the relationship as:

   * duplicate
   * update
   * contradiction
   * unrelated

Duplicate:

```text
do not create unnecessary duplicate
```

Update/contradiction:

```text
insert new memory
old memory → superseded
old.superseded_by → new memory ID
```

Example:

```text
Old:
Yash prefers black.
ACTIVE

New:
Yash now prefers dark green.

Result:

black → SUPERSEDED
dark green → ACTIVE
```

Do not permanently delete historical memory.

If uncertain, do not automatically supersede.
